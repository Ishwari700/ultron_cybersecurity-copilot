# M11.5 Large Cybersecurity Answer UX & Research Quality-of-Life

## 1. Overview

Milestone M11.5 transforms the user interface for cybersecurity investigations, moving beyond simple chat bubbles into a rich, dedicated research response workspace. Large technical explanations—including extensive vulnerability analyses, multi-endpoint recon tables, exploit payloads, and remediation guidance—are rendered with high readability, precise formatting, and researcher-centric controls.

The frontend component `LargeResponseView.tsx` serves as the primary rendering and interaction surface for assistant responses in the chat stream.

---

## 2. Layout & Typography Mechanics

### 2.1 Infinite Vertical Scrolling & Clipping Elimination
- **Unbounded Height**: Containers expand dynamically based on content length. Fixed-height constraints (`max-height: 400px; overflow: hidden`) that previously clipped responses have been completely removed.
- **Scroll Container Containment**: The conversation history viewport manages vertical scrolling with smooth CSS scroll behavior.
- **Scroll Memory**: When new streaming tokens arrive, the user's manual scroll position is preserved. If the user scrolls up to review prior sections or code blocks, the viewport does not forcefully snap to the bottom.

### 2.2 Preserved Technical Formatting
- **Monospaced Code Blocks**: Formatted with syntax highlighting containers, dedicated code copy buttons, and language badges (`bash`, `python`, `json`, `sql`, `http`).
- **Markdown Tables**: Tables feature responsive horizontal overflow handling (`overflow-x: auto`), subtle borders, zebra-striping, and preserved cell alignment.
- **Long URLs and Hashes**: Protected with `overflow-wrap: break-word` and `word-break: break-all` CSS rules to prevent breaking container layouts.
- **Safe HTML Rendering**: All model-generated text is treated as untrusted content and sanitized. Raw HTML script execution or iframe injection is blocked.

## 3. Collapsible Technical Sections

For large structured reports, `LargeResponseView` automatically detects markdown headings and organizes sections into collapsible accordion panels:

- **Summary**: High-level vulnerability or assessment overview.
- **Technical Explanation**: In-depth vulnerability mechanics and root cause analysis.
- **Attack Surface**: Affected endpoints, parameters, and protocol interactions.
- **Evidence**: Raw HTTP request/response traces, logs, and artifacts.
- **Reasoning**: Falsification logic, epistemic hypotheses, and boundary conditions.
- **Mitigations**: Defensive controls, code patches, and configuration fixes.
- **References**: CVE, CWE, and OWASP references.
- **Limitations**: Assessment scope restrictions and experimental boundaries.

Each section header includes an expand/collapse toggle (`▼`/`▶`), word count, and a section-specific copy button (`Copy Section`).

## 4. Sticky Response Action Bar

Every assistant response features a persistent toolbar providing direct access to research utilities:

```
[ Copy Response ] [ Copy Code ] [ Download MD ] [ Download TXT ] [ 🔍 Find ] [ Diagnostic Metadata ℹ️ ]
```

### 4.1 Copy Controls
- **Copy Response**: Copies the complete markdown response to the system clipboard.
- **Copy Code**: Copies only code block contents, stripping prose explanations.
- **Copy Section**: Copies an individual collapsible section.

### 4.2 Download & Export
- **Download Markdown**: Downloads `<response_id>.md` formatted with research headers, timestamps, and model attribution.
- **Download TXT**: Downloads `<response_id>.txt` in clean, plaintext format.
- **Print-Friendly View**: Styled with `@media print` CSS rules hiding UI controls and sidebars for clean PDF export.

### 4.3 Find-in-Answer Search
- An embedded search bar allows interactive in-page search within long responses.
- Displays match count (e.g., `Match 2 of 7`).
- Includes Previous (`▲`) and Next (`▼`) navigation controls.
- Highlights search terms with high-contrast text markers.

## 5. Research Quality-of-Life Controls

### 5.1 Stop Generation
- When response status is `GENERATING` or `CONTINUING`, an active `■ Stop Generating` button appears in the toolbar.
- Immediately signals the server-side `CancellationToken`.
- Halts generation deterministically without dropping already generated chunks.
- Marks status as `USER_STOPPED`.

### 5.2 Manual Continuation
- If generation stopped due to token limit (`TOKEN_LIMIT`) or incomplete syntax without automatic continuation, an amber `▶ Continue Answer` button appears.
- Prompts the engine to continue from the exact trailing token sequence with zero overlap duplication.

### 5.3 Response Regeneration & Version History
- Researchers can click `🔄 Regenerate` to request an alternative generation from the model.
- Prior generations are not overwritten; they are preserved in `ResponseVersion`.
- Version selector dropdown (`Version 1/2`, `Version 2/2`) enables switching between historical attempts with full integrity.

### 5.4 Context-Aware Answer Actions
Below each completed response, quick-action buttons allow researchers to transform the answer into structured outputs:
- **Explain Deeper**: Expands on technical mechanics with increased depth.
- **Summarize**: Produces an executive summary.
- **Defensive Version**: Translates exploit analysis into defensive remediation code.
- **Extract Indicators**: Extracts IP addresses, endpoints, parameter names, and file paths.
- **Extract Evidence Claims**: Isolates factual empirical claims for observation verification.
- **Checklist**: Generates a reproducible step-by-step verification checklist.

*Note: All answer actions initiate new model reasoning requests and never mutate canonical evidence, finding verification statuses, or authorization records.*

### 5.5 Follow-Up Suggestions
Clickable follow-up suggestion pills appear at the bottom of the answer (e.g., `"Show curl command"`, `"What is the root cause?"`, `"Is this in scope?"`), allowing rapid iterative investigation.

---

## 6. Diagnostic Metadata Panel

An expandable diagnostic drawer provides researchers with technical execution details:
- **Model**: Identifier (e.g., `qwen2.5-coder:7b`).
- **Status**: `COMPLETED`, `CONTINUING`, `TOKEN_LIMIT`, `USER_STOPPED`.
- **Termination Reason**: `NATURAL_STOP`, `LENGTH_CEILING`, `USER_ABORT`.
- **Chunks Generated**: Total count of sequential chunks and their sequence hashes.
- **Cumulative Tokens**: Total token count generated across all chunks.
- **Generation Latency**: Milliseconds elapsed across generation turns.
