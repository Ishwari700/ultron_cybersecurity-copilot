# M11.5 Configuration & Hardware Tuning Guide

## 1. Overview

Milestone M11.5 introduces fine-grained configuration parameters governing response chunking, continuation loops, overlap windows, and streaming timeouts. These settings ensure predictable performance, prevent runaway continuation loops, and guarantee stability on resource-constrained local hardware.

---

## 2. Configuration Parameters

All settings are configured via environment variables or initialized with defaults in `src/response/generator.py`, `src/response/completeness.py`, and `src/response/merger.py`:

| Parameter | Environment Variable | Default | Type | Description |
| :--- | :--- | :--- | :--- | :--- |
| `MAX_CONTINUATION_CHUNKS` | `BBAI_RESP_MAX_CHUNKS` | `8` | `int` | Maximum consecutive continuation chunks allowed in a single automatic continuation loop. |
| `MAX_CUMULATIVE_TOKENS` | `BBAI_RESP_MAX_CUMULATIVE_TOKENS` | `4096` | `int` | Global cumulative token ceiling across all chunks in a response session. Prevents context drift and memory blowup. |
| `MAX_CONTEXT_REPACKING_ATTEMPTS` | `BBAI_RESP_MAX_REPACK_ATTEMPTS` | `3` | `int` | Maximum retry attempts if continuation context framing fails or exceeds prompt limits. |
| `DEFAULT_CHUNK_TOKENS` | `BBAI_RESP_CHUNK_TOKENS` | `512` | `int` | Number of tokens requested per individual chunk (`num_predict`). Optimized for 4GB VRAM GPU latency. |
| `DEFAULT_TEMPERATURE` | `BBAI_RESP_TEMPERATURE` | `0.2` | `float` | Default temperature for deterministic technical reasoning and code generation. |
| `STREAM_TIMEOUT_SECONDS` | `BBAI_RESP_STREAM_TIMEOUT` | `60` | `int` | Maximum seconds allowed for an individual streaming chunk before raising `ResponseTimeoutError`. |
| `MIN_EXACT_OVERLAP` | `BBAI_RESP_MIN_OVERLAP` | `4` | `int` | Minimum character length required to confirm an exact suffix-prefix continuation overlap. |
| `MAX_OVERLAP_WINDOW` | `BBAI_RESP_MAX_OVERLAP_WINDOW` | `400` | `int` | Maximum characters at tail of previous chunk and head of next chunk inspected for duplicate overlap. |
| `AUTO_CONTINUATION_ENABLED` | `BBAI_RESP_AUTO_CONTINUATION` | `true` | `bool` | Whether the engine automatically triggers continuation upon detecting an incomplete response. |

## 3. Hardware Profile Tuning (4 GB VRAM GPU)

The platform is optimized for the target hardware profile:
- **Processor**: AMD Ryzen 5 5600H (6 cores / 12 threads)
- **System RAM**: 24 GB DDR4
- **Graphics Card**: NVIDIA GeForce RTX 3050 Laptop GPU (4 GB GDDR6 VRAM)
- **Local LLM Engine**: Ollama (`qwen2.5-coder:7b` / `qwen2.5-coder:3b` / `deepseek-r1:7b`)

### 3.1 VRAM Allocation & Concurrency Guard
- **Strict Concurrency = 1**: The platform strictly serializes LLM requests. Multiple concurrent inference requests on 4GB VRAM will trigger CUDA Out-Of-Memory errors or force model swapping between VRAM and system paging.
- **Chunk Token Ceiling (`DEFAULT_CHUNK_TOKENS=512`)**: Generating 512 tokens per chunk takes approximately 8–12 seconds on the RTX 3050. This provides responsive chunk arrival times without locking the GPU pipeline for long spans.
- **KV Cache Memory Budget**: A context window of 4,096 tokens fits comfortably within the 4GB VRAM envelope when running 4-bit quantized models (`qwen2.5-coder:7b-instruct-q4_K_M`).

## 4. Environment File Example (`.env`)

```bash
# M11.5 Long Response Configuration
BBAI_RESP_MAX_CHUNKS=8
BBAI_RESP_MAX_CUMULATIVE_TOKENS=4096
BBAI_RESP_CHUNK_TOKENS=512
BBAI_RESP_TEMPERATURE=0.2
BBAI_RESP_STREAM_TIMEOUT=60
BBAI_RESP_AUTO_CONTINUATION=true
BBAI_RESP_MIN_OVERLAP=4
BBAI_RESP_MAX_OVERLAP_WINDOW=400

# Concurrency Guard
BBAI_LLM_CONCURRENCY=1
```

## 5. Verification & Telemetry Inspection

Researchers can verify current runtime response metrics and configurations via the REST API:

```bash
curl -X GET http://localhost:8000/api/responses/metrics
```

Example JSON response:
```json
{
  "response_generation_count": 42,
  "response_continuation_count": 18,
  "response_total_tokens": 14250,
  "response_overlap_stripped_count": 14,
  "response_user_stopped_count": 2,
  "response_timeout_count": 0,
  "avg_generation_latency_ms": 3120.5
}
```
All telemetry metrics are scrubbed using `RedactionVault` to ensure zero API keys, passwords, or session tokens are ever leaked to monitoring logs.
