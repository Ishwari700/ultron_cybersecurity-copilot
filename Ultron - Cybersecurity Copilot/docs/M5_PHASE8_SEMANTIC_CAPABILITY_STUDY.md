## 1. Executive Summary & Objective

In Milestone M5 Phase 7, the confirmatory benchmark of the corrected reasoning architecture achieved:
- **336 / 336** completed live LLM calls.
- **0 / 336 (0.00%)** parser failures (completely eliminating the M4.9 composition defect).
- **224 / 336 (66.67%)** fully valid schema, protocol, and policy executions.
- **104 candidate HYPOTHESIS attempts**.
- **0 / 104 (0.00%)** candidate hypotheses passing typed experiment polarity and category compatibility semantics.
- **Useful Hypothesis Yield @ N reviewer minutes = 0.0000**.
- **200 / 224** valid executions classified as `EXPLORATORY_EVALUATION_APPLICABLE`.
- **0 / 224** valid executions classified as `VULNERABILITY_EVALUATION_APPLICABLE`.

The dominant empirical bottleneck revealed by Phase 7 was that **every candidate hypothesis generated by the frozen 7B model failed typed experiment construction semantics**.

Phase 8 was executed as a controlled diagnostic study to determine whether that failure is primarily associated with:
1. **Category/action selection burden**
2. **Supporting/disproving polarity burden**
3. **Output representation complexity**
4. **300-token single-call constraint**
5. **Prompt representation**
6. **Model capability under the frozen `qwen2.5-coder:7b` configuration**
7. **Lack of active empirical evidence in initial observations**

### Key Empirical Findings of Phase 8:

1. **Deterministic Failure Attribution (Phase 8.1)**:
   - **$65.38\%$ (68 / 104)** of candidate rejections were caused by **`CATEGORY_ACTION_INCOMPATIBILITY`**: the model selected generic actions (e.g. `TAMPER_REQUEST_PARAMETER`) that are illegal for the vulnerability class.
   - **$25.00\%$ (26 / 104)** were caused by **`OUTCOME_POLARITY_INVERSION`**: the model selected a legal action but inverted the logical outcome (e.g. asserting `HTTP_403_FORBIDDEN` proves BOLA or `HTTP_409_CONFLICT` confirms state transitions).
   - **$9.62\%$ (10 / 104)** were caused by **`IDENTICAL_SUPPORTING_DISPROVING_OUTCOME`**: the model emitted identical outcome strings, failing discriminability.
   - **$0.00\%$ (0 / 104)** were caused by truncation, missing semantic fields, or syntax errors.

2. **Controlled Semantic Protocol Study (Phase 8.2 — 40 Live Calls)**:
   - **Condition P3 (Engine-Supplied Action) achieved a 28.6% Typed Experiment Validity Rate** ($2 / 7$ candidate hypothesis attempts produced fully valid, un-inverted typed hypotheses passing all polarity checks). Both valid proposals occurred in Track A (`API-BOLA-001`).
   - By contrast, **Conditions P1 (Baseline) and P2 (Prompt Vocabulary Guidance) achieved 0.0% Typed Experiment Validity**. Adding vocabulary guidance to the prompt failed to eliminate polarity errors and caused $3 / 10$ schema failures due to prompt bloat.
   - **Condition P4 (Compact Representation)** achieved the highest overall execution validity rate ($70.0\%$) and lowest latency ($24.60\text{ s}$), but without engine-supplied actions, all hypothesis attempts failed polarity.

3. **Active-Evidence Diagnostic (Phase 8.3 — 4 Live Calls)**:
   - When canonical Class-1 anomaly evidence was injected, the model recognized the anomaly and attempted `decision: HYPOTHESIS` in **$4 / 4$ cases (100.0%)**, shifting intent away from abstention.
   - However, under unguided zero-shot conditions, all 4 attempts failed typed experiment construction ($4 / 4$ polarity failures).
   - **Conclusion on Evidence**: Lack of empirical anomaly evidence explains why the model abstains to `INSUFFICIENT_EVIDENCE` in 67% of cases, but does **NOT** explain why experiment construction fails when a hypothesis is attempted.

4. **Latency Envelope Audit (Phase 8.4)**:
   - An audit of frozen planning documents ([`docs/M1_5_M2_PLAN.md`](docs/M1_5_M2_PLAN.md) §12.4 and [`docs/M3_v2_3_6_PLANNING_HARDENING_AUDIT.md`](docs/M3_v2_3_6_PLANNING_HARDENING_AUDIT.md) §11.2) established that the 25-second figure is an **engineering performance target / profiling metric, NOT a hard disqualification gate**.
   - The hard execution gate is 30.0s (`LATENCY_TIMEOUT`). Phase 7 had zero timeouts.

## 7. Synthesis: Failure Mode Disambiguation

The combined evidence from Phase 8.1, 8.2, 8.3, and 8.4 allows us to systematically evaluate the six candidate failure causes:

| Candidate Cause | Diagnostic Evidence | Verdict & Attribution |
| :--- | :--- | :--- |
| **A. Model Semantic Capability Limitation** | The frozen `qwen2.5-coder:7b` model lacks the zero-shot reasoning capacity to simultaneously select a vulnerability action and non-inverted safe/breach outcomes from memory. | **CONFIRMED (Underlying Constraint)** |
| **B. Protocol Representation Burden** | JSON_BAIR achieved 0% parser errors in Phase 7. Compact representation (P4) improved latency but did not fix polarity inversions. Output syntax itself is not the bottleneck. | **REFUTED as Primary Cause** |
| **C. Category/Action Selection Burden** | 65.38% of Phase 7 failures were illegal actions. Offloading action selection to the deterministic engine (P3) produced a **28.6% valid typed hypothesis rate**. | **CONFIRMED (Primary Protocol Driver, 65.4%)** |
| **D. Polarity Representation Burden** | 25.00% of Phase 7 failures were inverted breach/safe outcomes. Model frequently asserts `HTTP_403` confirms BOLA or `HTTP_409` confirms state bugs. | **CONFIRMED (Secondary Driver, 25.0%)** |
| **E. Token-Budget Pressure** | Exactly 0 / 104 Phase 7 hypothesis attempts were truncated mid-generation. P4 reduced latency from 30s to 24s, but token limits did not cause the semantic rejections. | **REFUTED as Cause of Polarity Failure** |
| **F. Lack of Active Empirical Evidence** | In Phase 8.3, active canonical anomaly evidence caused the model to propose `HYPOTHESIS` in 100% of cases, but all 4 still failed typed experiment polarity. | **REFUTED as Cause of Experiment Failure** (Explains abstention rate, not experiment construction) |

### Core Architectural Conclusion:
The failure of Phase 7 candidate hypotheses was **NOT** caused by parser errors, schema defects, token truncation, or lack of active evidence. It was driven by the cognitive burden of asking a local 7B model to solve a joint discrete optimization problem: simultaneously choosing a category-legal action and a logically sound supporting/disproving outcome pair. 

When the deterministic engine fixes the legal experiment action (Condition P3), the model's experiment construction capability is unlocked, producing valid, un-inverted hypotheses without compromising verification rigor.
